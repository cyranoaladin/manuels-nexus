\section*{QCM d'auto-évaluation --- Interactions homme-machine sur le Web}

\begin{center}
\textit{Pour chaque question, une seule réponse est exacte. Entourez la lettre correspondante.}
\end{center}

\bigskip

\subsection*{C1/C2 --- Composants et événements}

\begin{enumerate}

\item \textbf{[Q1]} Le comportement d'un bouton lorsqu'on clique dessus est généralement programmé :
  \begin{enumerate}[label=\Alph*.]
    \item directement dans le code HTML.
    \item en JavaScript, via un gestionnaire d'événement.
    \item dans la feuille de style CSS.
    \item il n'est jamais possible de programmer un tel comportement.
  \end{enumerate}

\bigskip

\subsection*{C4 --- Client-serveur}

\item \textbf{[Q2]} Le code exécuté \textbf{sur le serveur} :
  \begin{enumerate}[label=\Alph*.]
    \item est visible dans le code source de la page reçue par le navigateur.
    \item n'est jamais visible par l'utilisateur.
    \item s'exécute toujours après le code JavaScript du client.
    \item ne peut jamais accéder à une base de données.
  \end{enumerate}

\bigskip

\subsection*{C6 --- Chiffrement}

\item \textbf{[Q3]} Le protocole HTTPS garantit que :
  \begin{enumerate}[label=\Alph*.]
    \item les données sont illisibles pour un intermédiaire pendant la transmission.
    \item le serveur stocke les données de façon sécurisée.
    \item aucune donnée personnelle n'est jamais collectée.
    \item le site est fiable et digne de confiance.
  \end{enumerate}

\bigskip

\subsection*{C8 --- GET et POST}

\item \textbf{[Q4]} Les paramètres d'une requête \lstinline{POST} sont :
  \begin{enumerate}[label=\Alph*.]
    \item visibles dans l'URL de la page.
    \item placés dans le corps de la requête, invisibles dans l'URL.
    \item toujours chiffrés automatiquement.
    \item limités à un seul paramètre.
  \end{enumerate}

\bigskip

\subsection*{C9 --- Choix du type de requête}

\item \textbf{[Q5]} Pour transmettre un mot de passe lors d'une connexion, il est recommandé d'utiliser :
  \begin{enumerate}[label=\Alph*.]
    \item GET, car c'est la méthode la plus simple.
    \item POST, pour ne pas exposer le mot de passe dans l'URL.
    \item indifféremment GET ou POST, cela n'a aucune importance.
    \item aucune des deux, un mot de passe ne doit jamais être transmis.
  \end{enumerate}

\bigskip

\item \textbf{[Q6]} Une recherche de produits sur un site marchand (mots-clés, filtres) utilise généralement :
  \begin{enumerate}[label=\Alph*.]
    \item GET, car les critères ne sont pas confidentiels et l'URL peut être partagée.
    \item POST, systématiquement, quelle que soit la nature des données.
    \item ni GET ni POST : uniquement des cookies.
    \item un formulaire sans méthode définie.
  \end{enumerate}

\end{enumerate}
