\textbf{1.} On compte une comparaison par tour de boucle :
\begin{python}
def recherche_liste(liste, valeur):
    comparaisons = 0
    for i in range(len(liste)):
        comparaisons = comparaisons + 1
        if liste[i] == valeur:
            return i, comparaisons
    return None, comparaisons
\end{python}

\textbf{2.} \lstinline{recherche_liste(badges, "B07")} renvoie
$(0\,;\,1)$, \lstinline{"B58"} donne $(4\,;\,5)$ et \lstinline{"B99"} donne
$(\text{None}\,;\,5)$. Le maximum de comparaisons est atteint deux fois : pour
le dernier élément, et pour une valeur \emph{absente} — dans ce dernier cas la
boucle va nécessairement jusqu'au bout, puisqu'on ne peut conclure à l'absence
qu'après avoir tout examiné.

\textbf{3.} La table s'obtient par compréhension, et la recherche par

\begin{python}
table = {code: i for i, code in enumerate(badges)}

def recherche_dict(table, valeur):
    return table.get(valeur)

\textbf{4.} Avec $1\,000$ badges, la recherche d'un badge absent demande
$1\,000$ comparaisons dans la liste, et \textbf{une seule} consultation dans le
dictionnaire.

La raison est que le dictionnaire ne compare pas : il \emph{calcule}. La clé est
transformée en un nombre par une fonction de hachage, ce nombre désigne
directement l'emplacement où la valeur devrait se trouver, et il suffit alors de
regarder cet emplacement. Le temps ne dépend donc pas du nombre de badges. La
liste, elle, n'a d'autre moyen que de parcourir.

\textbf{5.} \lstinline{recherche_liste(["B07", "B12", "B07"], "B07")} renvoie
$(0\,;\,1)$ : elle s'arrête à la première occurrence et ignore la seconde. Le
dictionnaire construit à partir de cette liste n'a que \textbf{deux} entrées, et
\lstinline{table["B07"]} vaut $2$ : la seconde occurrence a écrasé la première.

Les deux structures ne représentent donc pas la même chose. Une liste est une
suite \emph{ordonnée} qui accepte les doublons ; un dictionnaire est un ensemble
d'associations à clés \emph{uniques}, sans ordre significatif. Remplacer l'une
par l'autre pour gagner en rapidité, c'est aussi changer ce que la donnée peut
dire — et ici, perdre silencieusement un badge.
