\begin{exercice}{1NSI-ADGK-EX-005}{3}{15}
Le problème du \textbf{sac à dos} : on dispose d'objets, chacun avec un poids et une
valeur, et d'un sac de capacité limitée. On veut maximiser la valeur totale des objets
emportés sans dépasser la capacité. Une approche gloutonne classique choisit les objets par
\textbf{rapport valeur/poids décroissant}.
\begin{python}
def sac_a_dos_glouton(objets, capacite):
    """objets : liste de (nom, poids, valeur)."""
    objets_tries = sorted(objets, key=lambda o: o[2] / o[1], reverse=True)
    charge = 0
    valeur_totale = 0
    choisis = []
    for nom, poids, valeur in objets_tries:
        if charge + poids <= capacite:
            choisis.append(nom)
            charge += poids
            valeur_totale += valeur
    return choisis, valeur_totale
\end{python}
On dispose des objets \lstinline{X} (poids $6$, valeur $30$), \lstinline{Y} (poids $5$,
valeur $20$) et \lstinline{Z} (poids $5$, valeur $20$), pour un sac de capacité $10$.
\begin{enumerate}
  \item Calculer le rapport valeur/poids de chaque objet, et en déduire l'ordre dans lequel l'algorithme les examine.
  \item Exécuter \lstinline{sac_a_dos_glouton} sur ces données. Quels objets sont choisis, et quelle est la valeur totale obtenue ?
  \item Trouver, en cherchant à la main, une combinaison d'objets de poids total $\leqslant10$ offrant une valeur \textbf{strictement supérieure}. L'algorithme glouton est-il optimal dans ce cas ?
\end{enumerate}
\end{exercice}
