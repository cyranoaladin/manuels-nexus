\begin{corrige}{TNSI-HIST-EX-002}

\textbf{Q1.} Le processeur, la mémoire et l'écran sont les mêmes ; les
programmes utilisés et les traitements demandés changent. Cela illustre la
polyvalence de cette machine, mais ne suffit pas à établir une évolution
historique. Le Mark I de 1944, par exemple, recevait déjà des instructions
sur bande et pouvait effectuer différents calculs. La programmabilité ne
naît donc pas avec le smartphone.

\textbf{Q2.} Deux explications parmi les suivantes suffisent :
\begin{itemize}
  \item Le \textbf{système d'exploitation} gère l'accès aux ressources
    matérielles et propose des services communs aux applications.
  \item Une \textbf{machine virtuelle d'exécution}, comme la JVM, prend en
    charge un format d'instructions intermédiaire. Une réalisation adaptée
    à la machine permet de l'exécuter sans exposer directement tous les
    détails de ce matériel au programme.
  \item Le \textbf{navigateur} peut afficher une interface décrite en HTML
    et CSS et exécuter du code JavaScript. Il offre ainsi un environnement
    pour des applications web compatibles.
  \item Le \textbf{compilateur} traduit un programme source vers un langage
    cible, par exemple des instructions machine ou un format intermédiaire.
\end{itemize}
Une contrainte reste nécessaire : mémoire suffisante, processeur compatible,
interface logicielle disponible ou présence du capteur utilisé, par exemple.
Installer un logiciel ne crée pas un capteur absent. D'autres contraintes
correctement expliquées sont acceptables.
