\textbf{Q1.} Une \textbf{relation} est une table regroupant des tuples décrits par les mêmes attributs. Un \textbf{attribut} est une colonne de la relation, définie sur un domaine. Une \textbf{clé primaire} est un attribut (ou groupe d'attributs) dont la valeur identifie de façon unique chaque tuple.

\textbf{Q2.} \texttt{Commande.id\_client} est une clé étrangère vers \texttt{Client.id} : elle permet de savoir quel client a passé chaque commande, sans dupliquer les informations du client dans la table \texttt{Commande}.
\end{corrige}

\begin{corrige}{TNSI-BDD-EVAL-A-EX3}
\textbf{Q1.} La \textbf{structure} est le schema : la table \lstinline{Inscription} et ses
quatre attributs avec leurs types. Le \textbf{contenu} est l'ensemble des lignes
enregistrees. Une inscription supplementaire ajoute une ligne : elle change le
\textbf{contenu}, pas la structure. Changer la structure demanderait un
\lstinline{ALTER TABLE} ou un \lstinline{CREATE TABLE}.

\textbf{Q2.} Deux anomalies :
\begin{itemize}
  \item \textbf{redondance et anomalie de mise a jour} : l'email d'un adherent est repete a
  chacune de ses inscriptions. Corriger l'email sur une seule ligne laisse la base avec deux
  emails différents pour la même personne ;
  \item \textbf{anomalie de suppression} : supprimer la derniere inscription d'un adherent
  efface aussi son nom et son email, seule trace de son existence dans la base.
\end{itemize}
Le schema corrige separe les deux entites :
\begin{sql}
CREATE TABLE Adherent(
  id INTEGER PRIMARY KEY,
  nom TEXT,
  email TEXT
);
CREATE TABLE Participation(
  id INTEGER PRIMARY KEY,
  id_adherent INTEGER,
  activite TEXT,
  tarif REAL,
  FOREIGN KEY(id_adherent) REFERENCES Adherent(id)
);
\end{sql}
L'email n'est alors stocke qu'une fois, et un adherent survit a la suppression de toutes ses
participations.

\textbf{Q3.} Composant par composant :
\begin{itemize}
  \item \lstinline{SELECT activite, COUNT(*)} : la \textbf{projection}, qui dit quelles
  colonnes composent le résultat -- ici l'activite et un comptage ;
  \item \lstinline{FROM Inscription} : la \textbf{source} des lignes ;
  \item \lstinline{WHERE tarif > 20} : le \textbf{filtre}, applique aux lignes
  \textbf{avant} tout regroupement ;
  \item \lstinline{GROUP BY activite} : le \textbf{regroupement}, qui rassemble les lignes
  restantes par activite pour que \lstinline{COUNT(*)} compte a l'interieur de chaque groupe ;
  \item \lstinline{ORDER BY activite} : le \textbf{tri} du résultat final.
\end{itemize}
Sans le \lstinline{WHERE}, l'activite \og Echecs \fg{} apparaitrait aussi : le filtre agit
bien avant le regroupement.
\end{corrige}
