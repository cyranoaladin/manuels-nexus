% FICHE DE REMEDIATION — C5 : lire la documentation, ne pas deviner
%---------------------------------------------------------------

\textbf{Ce qui bloque.} Tu conclus d'après le nom de la fonction. Un nom suggère une intention,
jamais un contrat : il ne dit ni le type des arguments, ni la valeur renvoyée, ni les cas
d'erreur. Et devant l'incertitude, tu recopies le code trouvé — ce qui prive de toute
correction ultérieure et alourdit le programme, alors qu'un import suffit.

\textbf{À retenir.} Quatre choses à lire, dans cet ordre : les paramètres, la valeur de retour,
les conditions d'emploi, un exemple. Puis un essai borné sur une valeur dont tu connais déjà
la réponse.

\begin{exercice}{1NSI-LANG-RE-C5-EX1}{1}{10}
La documentation annonce : \lstinline{randint(a, b)} renvoie un entier aléatoire $N$ tel que
$a \leq N \leq b$, bornes comprises.
\begin{enumerate}
  \item Un élève écrit \lstinline{randint(1, 6)} pour simuler un dé et affirme que le $6$ ne
        sort jamais. Que lui répondre, en citant la documentation ?
  \item Écrire l'import nécessaire, puis l'appel simulant un dé à vingt faces.
  \item Proposer un essai qui vérifie, sans lire le code de la bibliothèque, que les deux
        bornes sont bien atteignables.
\end{enumerate}
\end{exercice}
