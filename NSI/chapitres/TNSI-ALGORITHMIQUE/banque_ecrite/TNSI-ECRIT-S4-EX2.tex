\section*{Sujet S4 --- Exercice 2 : diviser pour régner sur un tableau trié}

\textit{Durée conseillée : 70 minutes. Cet exercice est indépendant des deux
autres du sujet.}

\medskip
\textit{Contenu original Nexus --- ce n'est pas un sujet officiel d'examen.}

\subsection*{Énoncé}

Un capteur enregistre des écarts de température, rangés par ordre croissant.
On veut trouver le \textbf{point de bascule} : le plus petit indice à partir
duquel les valeurs cessent d'être négatives.

Exemple : sur $[-9, -4, -1, 0, 3, 8, 12]$, la bascule est à l'indice $3$.

\begin{enumerate}
  \item Écrire \lstinline{bascule(tableau)} par dichotomie. La fonction renvoie
    \lstinline{len(tableau)} si toutes les valeurs sont négatives, et $0$ si
    aucune ne l'est. Vérifier sur $[-9, -4, -1, 0, 3, 8, 12]$,
    $[-3, -2, -1]$, $[0, 1, 2]$ et le tableau vide.

  \item Compter le nombre de comparaisons effectuées sur le tableau de sept
    valeurs, puis sur un tableau de mille valeurs allant de $-500$ à $499$.
    Donner ensuite le nombre de comparaisons dans le \textbf{pire cas} sur
    mille valeurs, et relier cette borne à une puissance de $2$.

  \item À chaque tour de boucle, deux propriétés restent vraies : toutes les
    valeurs strictement avant \lstinline{gauche} sont négatives, et toutes
    celles à partir de \lstinline{droite} sont positives ou nulles. Écrire ces
    deux propriétés sous forme d'assertions dans la boucle. Expliquer ce
    qu'elles garantissent au moment où la boucle s'arrête.

  \item Écrire \lstinline{fusionner(a, b)}, qui fusionne deux tableaux triés en
    un seul, puis \lstinline{tri_fusion(tableau)} par la méthode diviser pour
    régner. Vérifier sur $[5, 2, 9, 1, 7]$. Un élève écrit
    \lstinline{if a[i] < b[j]} au lieu de \lstinline{<=} : le tri reste-t-il
    correct ? Que perd-on ?

  \item Appliquer \lstinline{bascule} à $[3, -1, 5, -2]$. Le résultat est-il le
    bon ? La fonction signale-t-elle un problème ? Que faut-il vérifier avant
    d'appeler une recherche dichotomique, et pourquoi cette vérification n'est
    généralement pas faite dans la fonction elle-même ?
\end{enumerate}

\subsection*{Corrigé}

\textbf{Question 1.} \emph{(5 points)}

\begin{python}
def bascule(tableau):
    gauche, droite = 0, len(tableau)
    while gauche < droite:
        milieu = (gauche + droite) // 2
        if tableau[milieu] < 0:
            gauche = milieu + 1
        else:
            droite = milieu
    return gauche
\end{python}

Résultats : $3$, $3$, $0$, $0$.

\medskip
\emph{Barème :} $2$ points pour l'encadrement \lstinline{[gauche, droite[},
$2$ pour les deux mises à jour, $1$ pour les quatre cas.

\medskip
\textbf{Question 2.} \emph{(4 points)}

Sept valeurs : $\mathbf{3}$ comparaisons. Mille valeurs, bascule au milieu :
$\mathbf{9}$.

Attention à ne pas confondre ce compte avec la borne. L'intervalle est
\textbf{divisé par deux} à chaque tour, donc le nombre de tours est au plus le
plus petit $k$ tel que $2^{k} \geqslant n + 1$. Pour $n = 1000$, cela donne
$k = 10$, puisque $2^{9} = 512 < 1001 \leqslant 1024 = 2^{10}$. Selon la
position de la bascule, on observe $9$ ou $10$ comparaisons : $9$ ici, $10$
dans le pire cas.

\medskip
\textbf{Question 3.} \emph{(4 points)}

\begin{python}
while gauche < droite:
    assert all(v < 0 for v in tableau[:gauche])
    assert all(v >= 0 for v in tableau[droite:])
    ...
\end{python}

Quand la boucle s'arrête, \lstinline{gauche == droite}. Les deux propriétés
disent alors : tout ce qui est avant cet indice est négatif, tout ce qui est à
partir de cet indice ne l'est pas. C'est exactement la définition du point de
bascule — l'invariant \textbf{prouve} le résultat, il ne se contente pas de le
suggérer.

\medskip
\textbf{Question 4.} \emph{(5 points)}

\begin{python}
def fusionner(a, b):
    resultat, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            resultat.append(a[i]); i += 1
        else:
            resultat.append(b[j]); j += 1
    return resultat + a[i:] + b[j:]

def tri_fusion(tableau):
    if len(tableau) <= 1:
        return list(tableau)
    milieu = len(tableau) // 2
    return fusionner(tri_fusion(tableau[:milieu]),
                     tri_fusion(tableau[milieu:]))
\end{python}

$[5, 2, 9, 1, 7]$ donne $[1, 2, 5, 7, 9]$.

Avec \lstinline{<} strict, le tri reste \textbf{correct} : les valeurs sont
toujours triées. On perd la \textbf{stabilité} — à valeur égale, l'élément
venu de la moitié gauche ne passe plus en premier. Sur des couples
$(\text{a}, 1), (\text{b}, 2)$ et $(\text{c}, 1)$, on obtient
$\text{c}, \text{a}, \text{b}$ au lieu de $\text{a}, \text{c}, \text{b}$.

\medskip
\textbf{Question 5.} \emph{(2 points)}

Sur $[3, -1, 5, -2]$, la fonction renvoie une valeur, et cette valeur n'a
aucun sens : le tableau n'est pas trié, donc le « point de bascule » n'existe
pas. Aucun problème n'est signalé.

Il faut vérifier que le tableau est trié. Cette vérification n'est pas faite
dans la fonction parce qu'elle coûterait un parcours complet — soit
exactement ce que la dichotomie évite. Elle relève de la
\textbf{précondition} : c'est à l'appelant de la garantir.

\subsection*{Critique}

\begin{itemize}
  \item \textbf{L'encadrement.} Écrire \lstinline{droite = len(tableau) - 1}
    change tout : le cas « aucune valeur positive » n'est plus atteignable, et
    la fonction renvoie un indice au lieu de \lstinline{len(tableau)}.
  \item \textbf{\lstinline{droite = milieu - 1}.} Erreur classique et
    silencieuse : elle saute la valeur du milieu, qui est justement candidate.
    Les quatre cas de la question 1 la démasquent.
  \item \textbf{Confondre correction et stabilité.} La question 4 attend les
    deux mots. Un tri instable n'est pas faux ; il est inutilisable dès qu'on
    trie en deux passes.
  \item \textbf{La question 5 récompense la retenue.} Ajouter la vérification
    dans la fonction est tentant et ruinerait son intérêt. L'attendu est de
    nommer la précondition, pas de la coder.
\end{itemize}

\subsection*{Portée pédagogique}

L'exercice réunit les deux usages de la division par deux : la recherche, qui
divise l'\emph{espace} du problème, et le tri, qui divise les \emph{données}.
Les mêmes trois lignes — couper, traiter, recoller — servent aux deux.

La question 3 est celle qui distingue un candidat qui code d'un candidat qui
prouve : l'invariant n'est pas une vérification supplémentaire, c'est la raison
pour laquelle l'algorithme est correct. La question 5 ferme l'exercice sur la
limite du procédé, et sur qui en porte la responsabilité.
