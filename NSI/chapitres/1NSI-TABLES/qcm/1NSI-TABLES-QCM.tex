\section*{\textcolor{chapcolor}{\MakeUppercase{Traitement de données en tables — QCM d'auto-évaluation}}}

\begin{center}
\textit{Pour chaque question, une seule réponse est exacte.}
\end{center}

\begin{enumerate}

\item[] \textbf{Capacité C1}

\item \textbf{[Q1]} Après import d'un fichier CSV avec \code{csv.DictReader}, la valeur de la colonne \code{age} écrite \code{16} dans le fichier est de type :
  \begin{enumerate}[label=\Alph*.]
    \item \code{int}
    \item \code{float}
    \item \code{str}
    \item \code{bool}
  \end{enumerate}

\item \textbf{[Q2]} Le « domaine de valeurs » d'une colonne d'une table désigne :
  \begin{enumerate}[label=\Alph*.]
    \item le nombre de lignes de la table.
    \item l'ensemble des valeurs que cette colonne peut prendre.
    \item le type Python de la colonne, et rien d'autre.
    \item le nom de la colonne dans le fichier CSV.
  \end{enumerate}

\item[] \textbf{Capacité C2}

\item \textbf{[Q3]} Pour extraire les lignes d'une table qui vérifient un critère, sans modifier la table de départ, l'outil adapté en Python est :
  \begin{enumerate}[label=\Alph*.]
    \item une compréhension de liste assortie d'une condition.
    \item une réécriture directe du fichier CSV.
    \item la fonction \code{sorted}.
    \item l'opérateur \code{+} entre les deux tables.
  \end{enumerate}

\item \textbf{[Q4]} Pour détecter les doublons sur la colonne \code{id} d'une table, il faut :
  \begin{enumerate}[label=\Alph*.]
    \item comparer chaque ligne entière à toutes les autres.
    \item trier la table par ordre alphabétique, puis compter les lignes.
    \item compter les occurrences de chaque valeur de la seule colonne \code{id}.
    \item supprimer toutes les lignes strictement identiques.
  \end{enumerate}

\item[] \textbf{Capacité C3}

\item \textbf{[Q5]} Que fait l'appel \code{sorted(table, key=lambda ligne: ligne["age"])} ?
  \begin{enumerate}[label=\Alph*.]
    \item Il trie \code{table} sur place et ne renvoie rien.
    \item Il provoque une erreur, car \code{table} contient des dictionnaires.
    \item Il ne trie que les colonnes numériques, jamais les chaînes.
    \item Il renvoie une nouvelle liste triée, sans modifier \code{table}.
  \end{enumerate}

\item[] \textbf{Capacité C4}

\item \textbf{[Q6]} Deux tables sont fusionnées sur une colonne commune. Par défaut, une ligne de \code{table1} dont la clé n'apparaît dans aucune ligne de \code{table2} :
  \begin{enumerate}[label=\Alph*.]
    \item n'apparaît pas dans le résultat.
    \item provoque l'arrêt du programme.
    \item apparaît dans le résultat, avec des valeurs vides pour les colonnes de \code{table2}.
    \item est recopiée deux fois dans le résultat.
  \end{enumerate}

\end{enumerate}

\subsection*{Diagnostic des réponses erronées}

\begin{itemize}
  \item \textbf{Q1}
  \begin{itemize}
    \item \textbf{A} — L'élève suppose que le lecteur CSV devine le type. Un fichier CSV ne contient que du texte : \code{csv.DictReader} renvoie toujours des chaînes, et la conversion en entier reste à la charge du programme. \emph{Renvoi : C1, import et typage des colonnes.}
    \item \textbf{B} — Même confusion qu'en A, avec en plus l'idée qu'un nombre lu serait flottant par défaut. Aucune conversion automatique n'a lieu à l'import. \emph{Renvoi : C1, import et typage des colonnes.}
    \item \textbf{D} — L'élève confond le type de la valeur et le résultat d'un test sur cette valeur. Une colonne ne devient booléenne que si le programme la convertit explicitement. \emph{Renvoi : C1, import et typage des colonnes.}
  \end{itemize}
  \item \textbf{Q2}
  \begin{itemize}
    \item \textbf{A} — L'élève confond le domaine, qui décrit la colonne, avec la taille de la table, qui décrit son contenu. \emph{Renvoi : C1, descripteur d'une table.}
    \item \textbf{C} — Le type est une contrainte parmi d'autres. Le domaine est plus fin : la colonne \code{mois} est de type entier, mais son domaine se limite aux valeurs de 1 à 12. \emph{Renvoi : C1, descripteur d'une table.}
    \item \textbf{D} — L'élève confond le descripteur, qui nomme la colonne, avec le domaine, qui délimite ses valeurs. \emph{Renvoi : C1, descripteur d'une table.}
  \end{itemize}
  \item \textbf{Q3}
  \begin{itemize}
    \item \textbf{B} — L'élève agit sur le fichier au lieu d'agir sur la table chargée en mémoire. Filtrer est une lecture : cela ne doit rien détruire à la source. \emph{Renvoi : C2, filtrage par compréhension.}
    \item \textbf{C} — L'élève confond filtrer et trier. \code{sorted} réordonne toutes les lignes ; il n'en supprime aucune. \emph{Renvoi : C2, filtrage par compréhension.}
    \item \textbf{D} — L'élève confond filtrer et concaténer. L'opérateur \code{+} allonge la table au lieu de la restreindre. \emph{Renvoi : C2, filtrage par compréhension.}
  \end{itemize}
  \item \textbf{Q4}
  \begin{itemize}
    \item \textbf{A} — L'élève compare les lignes entières. Deux inscriptions du même identifiant qui diffèrent par une seule autre colonne échappent alors à la détection, alors que ce sont précisément les doublons cherchés. \emph{Renvoi : C2, doublons sur une colonne.}
    \item \textbf{B} — Le tri rapproche les doublons mais ne les compte pas. Il reste à comparer les valeurs voisines de la colonne visée. \emph{Renvoi : C2, doublons sur une colonne.}
    \item \textbf{D} — L'élève traite les doublons avant de les avoir identifiés, et sur le mauvais critère : la ligne entière au lieu de la colonne \code{id}. \emph{Renvoi : C2, doublons sur une colonne.}
  \end{itemize}
  \item \textbf{Q5}
  \begin{itemize}
    \item \textbf{A} — L'élève confond \code{sorted} et la méthode \code{list.sort}. C'est \code{sort} qui trie sur place et renvoie \code{None} ; \code{sorted} construit une nouvelle liste. \emph{Renvoi : C3, tri suivant une colonne.}
    \item \textbf{B} — Le paramètre \code{key} sert exactement à cela : il extrait de chaque ligne la valeur à comparer, si bien que les dictionnaires ne sont jamais comparés entre eux. \emph{Renvoi : C3, tri suivant une colonne.}
    \item \textbf{C} — Le tri fonctionne sur toute donnée ordonnable, chaînes comprises, qui sont comparées dans l'ordre lexicographique. \emph{Renvoi : C3, tri suivant une colonne.}
  \end{itemize}
  \item \textbf{Q6}
  \begin{itemize}
    \item \textbf{B} — Une clé sans correspondance est un cas ordinaire de fusion, pas une anomalie : le programme continue, la ligne est simplement écartée. \emph{Renvoi : C4, fusion de deux tables.}
    \item \textbf{C} — L'élève décrit une fusion qui conserve toutes les lignes de la table de gauche. C'est une autre opération, qu'il faut programmer explicitement ; ce n'est pas le comportement par défaut. \emph{Renvoi : C4, fusion de deux tables.}
    \item \textbf{D} — La duplication survient lorsqu'une clé apparaît plusieurs fois dans \code{table2}, jamais lorsqu'elle en est absente. \emph{Renvoi : C4, fusion de deux tables.}
  \end{itemize}
\end{itemize}
