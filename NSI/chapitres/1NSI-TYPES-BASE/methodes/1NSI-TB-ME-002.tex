\begin{fichemethode}{M2}{Expliquer pourquoi un calcul sur des flottants ne tombe pas juste}

\textbf{Quand l'utiliser ?} Quand un programme affiche un résultat « presque » correct, ou
quand un test d'égalité entre nombres à virgule échoue alors que le calcul semble exact.

\textbf{Pas à pas :}
\begin{enumerate}
  \item \textbf{Ne cherche pas l'erreur dans le programme.} L'écriture est correcte ; c'est la
        \emph{représentation} des nombres qui est en cause.
  \item \textbf{Demande-toi si le nombre s'écrit exactement en base deux.} Un nombre décimal
        n'a une écriture binaire finie que si sa partie fractionnaire est une somme de
        $\frac{1}{2}$, $\frac{1}{4}$, $\frac{1}{8}$\ldots\ C'est le cas de $0{,}5$ et
        $0{,}75$ ; ce n'est pas le cas de $0{,}1$ ni de $0{,}2$.
  \item \textbf{Conclus} : la machine stocke une valeur \emph{approchée}, et les erreurs
        s'accumulent à chaque opération.
  \item \textbf{Remplace le test d'égalité} par une comparaison à une tolérance :
        vérifier que l'écart est plus petit qu'un seuil, plutôt que d'exiger l'égalité exacte.
\end{enumerate}

\textbf{Exemple rédigé.} \lstinline{0.1 + 0.2 == 0.3} est \textbf{faux} en Python. Ni
$0{,}1$ ni $0{,}2$ n'ont d'écriture binaire finie : leur somme approchée diffère de la valeur
approchée de $0{,}3$. En revanche \lstinline{0.5 + 0.25 == 0.75} est \textbf{vrai}, car ces
trois nombres s'écrivent exactement en base deux.

La bonne écriture du test :
\begin{python}
abs((0.1 + 0.2) - 0.3) < 1e-9
\end{python}

\textbf{Erreur fréquente.} Raisonner sur les décimaux exacts et conclure que le programme est
mal écrit. Il est syntaxiquement correct : le piège porte sur la valeur, pas sur l'écriture.

\end{fichemethode}
