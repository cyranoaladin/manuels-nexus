\begin{python}
def est_premier(n):
    """Indique si l'entier n (n > 1) est premier.

    Parametre : n, entier strictement superieur a 1.
    Renvoie : True si n est premier, False sinon.
    """
    for d in range(2, n):
        if n % d == 0:
            return False
    return True

print(est_premier(7))  # True
print(est_premier(8))  # False
\end{python}
\end{corrige}

\textbf{Q2.} Il faut \lstinline{pstdev} : l'énoncé demande de decrire \textbf{exactement les
quatre valeurs mesurees}, c'est-a-dire la population entiere. La documentation indique que
\lstinline{pstdev} divise par $n$, tandis que \lstinline{stdev} divise par $n-1$ parce qu'il

pour cela que \lstinline{stdev} rend ici une valeur strictement plus grande.

\textbf{Q1.} La phrase confond \textbf{calculabilite} et \textbf{commodite ou performance}.
Un probleme calculable l'est dans n'importe quel langage Turing-complet : Python, C, OCaml
ou un autre calculent exactement le même ensemble de fonctions. Ce qui change d'un langage a
l'autre, c'est la vitesse d'execution, la facilite d'ecriture ou les bibliotheques
disponibles -- jamais la frontiere de ce qui est calculable. Un probleme non calculable, comme
le probleme de l'arret, ne le devient pas davantage en C.

\textbf{Q2.} Pour une \textbf{interface graphique}, le paradigme \textbf{objet} (ou
evenementiel) convient : chaque composant a un etat qui evolue et des methodes qui reagissent
aux événements, ce que l'encapsulation exprime naturellement. Pour \textbf{filtrer et
transformer une longue liste de mesures}, le paradigme \textbf{fonctionnel} convient : la
transformation s'ecrit en une expression sans etat mutable, plus courte et plus sure a relire.
